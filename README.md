# how-ctc-beam-search-works

빔 서치는 무엇을 찾고 있는가 — Deep Speech 2의 디코딩. 신경망이 내놓는 「프레임마다의 문자 확률표」에서 문장 하나를 뽑아내는 과정을, CTC 축약 규칙부터 prefix beam search 알고리즘, `Q(y) = log p_ctc + α log p_lm + β·단어수`, 배포용 가지치기까지 브라우저에서 직접 돌려 보는 인터랙티브 교육 자료입니다.

## 한 문단 요약

DS2의 신경망은 문장을 출력하지 않습니다. **프레임마다 "이 40ms는 어떤 글자인가"라는 확률표**(알파벳 + `blank`)를 뱉을 뿐입니다. 여기서 프레임별 1등을 이어 붙이면(greedy) **틀립니다** — CTC에서 문장 `y`의 확률은 어느 한 정렬의 확률이 아니라 **`y`로 축약되는 모든 정렬의 확률 합**이기 때문입니다. 확률 질량이 여러 정렬에 흩어져 있으면 greedy는 그걸 모으지 못합니다. 그래서 정렬 대신 **문장 접두사**를 후보로 들고 다니며 같은 접두사의 확률을 합산하는 **prefix beam search**를 씁니다. 이때 접두사마다 확률을 `p_b`(blank로 끝남) / `p_nb`(글자로 끝남) 둘로 나눠 보관하는데, 다음 글자가 직전과 같을 때 병합될지 확장될지가 여기서 갈리기 때문입니다. 여기에 외부 5-gram 언어 모델과 단어 삽입 보너스를 더한 `Q(y) = log p_ctc(y|x) + α log p_lm(y) + β·word_count(y)`를 최대화합니다. 빔은 **영어 500 · 중국어 200**, 배포에서는 후보 글자를 **누적 확률 0.99까지·최대 40자**로 잘라 언어 모델 조회를 **150배** 줄였습니다 (CER 영향 상대 0.1~0.3%).

| §2 | CTC 축약 규칙 — ①연속 중복 병합 ②blank 제거, 그리고 순서가 중요한 이유 | 정렬을 직접 클릭해 만들며 축약 2단계와 "같은 문장을 만드는 정렬 개수·확률 합" 확인 |
| §3 | greedy는 왜 틀리는가 — 최선의 *정렬* ≠ 최선의 *문장* | 4⁶=4,096개 정렬 전수 열거. greedy는 `"ct"`(0.204), 실제 최선은 `"cat"`(0.425) |
| §4 | prefix beam search — `p_b`/`p_nb`를 나눠 드는 이유 + 의사코드 | **프레임 단위 스텝 실행기** — 빔 목록·신규·버려진 후보를 매 프레임 관찰 |

| §6 | 언어 모델 붙이기 — `Q(y)`의 세 항과 β가 필요한 이유 | α·β 슬라이더로 후보 5개 순위 뒤집기 ("recognize speech" vs "wreck a nice beach") |
| §7 | 배포 — 40ms마다 100만 번 조회를 어떻게 줄였나 | 가지치기 계산기 — 기본값에서 논문의 120만 회 → 8,000회 = **150.0×** 재현 |

## 이 페이지가 답하는 질문

- CTC의 `blank`는 무음인가? (아니다 — "출력할 글자 없음" 표시이자 같은 글자의 **경계 표시**)
- 왜 `t t`는 "t"가 되고 `t _ t`는 "tt"가 되는가?
- greedy가 틀리는 게 정확히 어떤 상황인가? (확률 질량이 여러 정렬로 흩어질 때)
- 왜 접두사마다 확률을 **두 개** 들고 다니는가?
- `β·word_count`는 왜 붙어 있는가? 없으면 무슨 일이 생기나?
- 논문의 "150배"는 어디서 나온 숫자인가? (`6000 ÷ 40`)
- 빔을 키우면 계속 좋아지는가? (아니다 — 금방 포화된다)
